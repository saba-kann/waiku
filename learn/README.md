# 揺れ判定の自己学習(まとめる/まとめない)

## 目的
声が2つ以上の高さを短く行き来する場面で、
「1音にまとめるべきか」「個々の音として残すべきか」を、
ユーザーの判断から少しずつ学習して自動化する。

## 設計
1. 揺れ区間を検出したら、features.py で特徴量にする
2. label_store.jsonl に溜まった過去の判断で分類器を学習する(train.py)
3. 確信度が高い(|score-0.5|が大きい)場面は自動処理する
4. 確信度が低い場面だけユーザーに音を聞かせて判定してもらい、
   答えを label_store.jsonl に追記して分類器を更新する
5. 繰り返すほど、ユーザーに聞く頻度が減っていくのが目標

## 特徴量(features.py の extract() が返すもの)
- duration        : 区間の長さ(秒)
- n_notes         : 区間内の音符の数
- pitch_range     : 最高音と最低音の差(半音)
- returns_to_start: 始点と終点が同じ高さか(0/1)
- rate_hz         : 音の切り替わり速度のおおよそ(Hz換算)
- is_repeat_block : 曲中の反復ブロック(歌詞の8回繰り返し句など)の中かどうか(0/1)
  ※わかっていれば渡す。反復ブロック内は「まとめない」が正解になりやすい
- voice_smooth    : 実際の声の音程が段差ではなく滑らかに動いているか(0-1の連続値)
  ※ portamento(音を滑らせる)の指標。高いほど「本来は1つの動き」の可能性が高い

## 教師データの記録形式(label_store.jsonl、1行1件)
{"duration":0.55,"n_notes":4,"pitch_range":2,"returns_to_start":1,
 "rate_hz":7.3,"is_repeat_block":0,"voice_smooth":0.82,
 "label":"keep_separate", "note":"前の方が良かったが完全ではない(2026-09-22)"}

label は "merge"(1音にまとめる) / "keep_separate"(個々の音を残す) / "uncertain"(判断保留) の3値。
"uncertain" は集計から外し、ユーザーに再確認を求める材料として別枠で使う。

## 今回の会話で得られた最初の教師データ
- 88〜106秒のトリル(0.16秒間隔、8分音符ぴったり、歌詞の反復ブロックと推定)
  → keep_separate。理由: 歌詞の繰り返し句である証拠(Whisperで別箇所の反復句と
    同じリズム構造を確認)があったため、まとめるのは誤りと判定
- 116〜130秒のE-4/E4/F4の山型(0.3〜1.3秒、始点=終点、声が滑らかに動く)
  → 判断保留。ユーザーは「まとめた方は良かったが元の方も完全ではなかった」と回答。
    どちらも不正解に近い、という珍しいケース。おそらく正解は「山を1つの音として
    書きつつ、ピッチベンドや装飾記号で滑りを表現する」という、今の音符だけの表現では
    そもそも書けない形。学習データとしては "uncertain" 扱いとし、
    表現形式(音符+ベンド)を用意できてから再度尋ねるべき

## 次にやること
1. features.py を実装(既存の mel_*.json とピッチ抽出データから特徴を計算する関数)
2. label_store.jsonl を作り、上記2件を最初のデータとして入れる
3. 揺れを検出するたびに、確信度が低ければユーザーに聞くフローを build.py に組み込む
4. データが10件を超えたら train.py で簡単な分類器(ロジスティック回帰で十分)を作る
